# i18n 対応計画（設定画面 UI）

## 背景・目的

Obsidian コミュニティプラグイン `nwt-linker` の設定画面 UI（`src/settings.ts`、`src/ui/confirm-modal.ts`）で使われている文字列が現在すべて英語のハードコードになっている。本タスクでは、これを日本語を含む多言語化（i18n）するための調査結果と実装計画をまとめる。

---

## 調査結果

### 現状

| 項目 | 状態 |
|---|---|
| 翻訳対象 UI ファイル | `src/settings.ts`（420 行）、`src/ui/confirm-modal.ts`（37 行） |
| 翻訳対象文字列数 | 約 40 個（設定名・説明文・ボタン・プレースホルダー・Notice メッセージ・エラーメッセージ） |
| 既存 i18n 基盤 | なし |
| 外部 i18n ライブラリ | 未導入 |
| Obsidian API | プラグイン向けの i18n API は提供されていない。`getLanguage()` 等で言語設定は取得可能 |

### Obsidian プラグインにおける一般的な i18n パターン

| アプローチ | 採用例 | 特徴 |
|---|---|---|
| **手作り TypeScript ロケールファイル** | Kanban、Excalidraw | 依存なし、型安全、コミュニティ標準 |
| **i18next** | Tasks | 機能豊富だがオーバースペック、バンドルサイズ増 |
| **obsidian-plugin-i18n** | — | 未成熟（v0.2.0、採用実績なし） |

### 推奨アプローチ

**手作り TypeScript ロケールファイル方式**を採用する。

理由:

- 外部依存ゼロで、AGENTS.md の「プラグインを小さく保つ」方針に合致する
- TypeScript で型安全に翻訳キーを管理できる
- esbuild で `main.js` にバンドル可能
- Obsidian コミュニティで広く使われている標準的なパターン

## 実装計画

### 1. 新規ファイル構成

```
src/
  i18n/
    index.ts              # t() 関数、言語検出、補間処理
    locales/
      en.ts               # 英語（ソース・オブ・トゥルース、型定義も担当）
      ja.ts               # 日本語
```

### 2. 各ファイルの責務

#### `src/i18n/locales/en.ts`

- すべての翻訳キーと英語原文を定義する
- `as const` により `TranslationKey` 型を導出する
- 他の言語ファイルはこの `TranslationKey` 型を満たすように実装する

例:

```typescript
const en = {
  'Enabled': 'Enabled',
  'Enable automatic scripture link conversion': 'Enable automatic scripture link conversion',
  'Failed to save setting: {error}': 'Failed to save setting: {error}',
  // ...
} as const;

export type TranslationKey = keyof typeof en;
export default en;
```

#### `src/i18n/locales/ja.ts`

- `TranslationKey` 型を満たす `Record<TranslationKey, string>` を実装する
- キーが不足している場合はコンパイルエラーとする

例:

```typescript
import type { TranslationKey } from './en';

const ja: Record<TranslationKey, string> = {
  'Enabled': '有効',
  'Enable automatic scripture link conversion': '聖書リンクの自動変換を有効にする',
  'Failed to save setting: {error}': '設定の保存に失敗しました: {error}',
  // ...
};

export default ja;
```

#### `src/i18n/index.ts`

- ユーザーの Obsidian 言語設定を取得する
- 言語コードに応じたロケールマップを保持する
- `t()` 関数を提供する
- `{placeholder}` 形式の簡易パラメータ補間に対応する

例:

```typescript
import en, { TranslationKey } from './locales/en';
import ja from './locales/ja';

const localeMap: Record<string, Record<TranslationKey, string>> = {
  en,
  ja,
};

function getCurrentLocale(): Record<TranslationKey, string> {
  const lang = window.localStorage.getItem('language') ?? 'en';
  return localeMap[lang] ?? en;
}

export function t(key: TranslationKey, params?: Record<string, string | number>): string {
  const template = getCurrentLocale()[key] ?? en[key] ?? key;
  if (!params) return template;

  return Object.entries(params).reduce((result, [name, value]) => {
    return result.replaceAll(`{${name}}`, String(value));
  }, template);
}
```

### 3. UI 側での置き換え

#### `src/settings.ts`

```typescript
import { t } from './i18n';

new Setting(containerEl)
  .setName(t('Enabled'))
  .setDesc(t('Enable automatic scripture link conversion'));
```

動的文字列は `t()` の第 2 引数で補間する:

```typescript
new Notice(t('Failed to save setting: {error}', { error: errorMessage }));
```

#### `src/ui/confirm-modal.ts`

- タイトルとボタンラベルを `t()` で囲む
- `message` は引数として受け取るため、呼び出し元で `t()` 済みの文字列を渡す

```typescript
import { t } from '../i18n';

contentEl.createEl('h3', { text: t('Confirm') });
const cancelBtn = buttonContainer.createEl('button', { text: t('Cancel') });
const confirmBtn = buttonContainer.createEl('button', { text: t('Confirm'), cls: 'mod-warning' });
```

### 4. 実装手順

1. `src/i18n/locales/en.ts` を作成し、すべての翻訳キーを定義する
2. `src/i18n/index.ts` を作成し、`t()` 関数と言語検出ロジックを実装する
3. `src/settings.ts` の全ハードコード文字列を `t()` に置き換える
4. `src/ui/confirm-modal.ts` の固定文字列を `t()` に置き換える
5. `src/i18n/locales/ja.ts` を作成し、日本語訳を追加する
6. `npm run lint` と `npm run build` で型チェック・リンティング・ビルドを確認する
7. 必要に応じて他の言語ファイル（zh-cn、ko など）を追加する

---

## 注意点

- `{{bible}}`、`{{wtlocale}}`、`{{pub}}` は URL テンプレートの構文であり、翻訳対象外とする
- `t()` は `{placeholder}` 形式の補間のみ対応とし、複雑な複数形や文脈依存は当面スコープ外とする
- 言語コードは Obsidian が使用している ISO 639-1 形式（`en`、`ja`、`zh-cn` など）に合わせる
- 未対応言語の場合は英語（`en`）にフォールバックする
- 翻訳キーは英語の原文をそのまま使用する Kanban 方式を採用し、可読性と保守性を両立する
